# SQL Server 實戰指南：Ch7_3_4 外鍵（FOREIGN KEY）關聯建置與排錯

> **⚠️ 重要型別宣告（必讀）**  
> 課本投影片（`Ch7_3_4.sql`）原始範例雖然寫的是 `char(4)`、`char(5)` 與 `varchar(8)`，但實際附加的【教務系統】資料庫中，**`班級` 及相關父表的文字欄位皆為 `nvarchar`**。  
> 因此本指南所有修正後的 SQL 指令均以 **`nvarchar`** 為準（`nvarchar(4)`、`nvarchar(5)`、`nvarchar(8)`），確保外鍵與主鍵的資料型別 100% 一致。

---

## 1. 任務目標（Ch7_3_4.sql）

在【教務系統】資料庫中建立【班級】資料表，並使用 `FOREIGN KEY` 條件約束，將【班級】與【學生】、【教授】、【課程】三張父表建立多對多關聯：

* **複合主鍵（Composite Primary Key）**：`(學號, 教授編號, 課程編號)`
* **外鍵關聯（Foreign Keys）**：
  1. `班級.學號` $\rightarrow$ 參照 `學生.學號`（行內寫法 `REFERENCES`）
  2. `班級.教授編號` $\rightarrow$ 參照 `教授.教授編號`（表層寫法 `FOREIGN KEY`）
  3. `班級.課程編號` $\rightarrow$ 參照 `課程.課程編號`（表層寫法 `FOREIGN KEY`）

---

## 2. 實作中遇到的 4 大問題與底層原因

在 SQL Server 2022（SSMS）直接執行課本指令時，會依序遇到以下問題（**注意：SQL Server 2022 的 `FOREIGN KEY` 語法並沒有改變，報錯全來自資料庫現況與型別**）：

| 階段 | 錯誤現象 / 訊息 | 底層原因分析 | 解決方式 |
| :--- | :--- | :--- | :--- |
| **1. 物件衝突與快取** | `資料庫中已經有一個名為 '班級' 的物件`（刪掉後錯誤清單仍有紅字） | 資料庫原本已存在舊版 `班級` 表；刪除後 SSMS 的 **IntelliSense 本地快取未即時同步**，導致「錯誤清單」持續顯示舊錯誤。 | 建表前加入 `IF OBJECT_ID(...) DROP TABLE` 防呆；執行結果一律看 **「訊息 (Messages)」** 分頁，並按 `Ctrl + Shift + R` 重新整理快取。 |
| **2. 父表缺少主鍵** | `參考資料表 '學生'/'教授'/'課程' 中，沒有與外部索引鍵相符的主要或候選索引鍵` | 關聯式資料庫強制規定：**外鍵只能參照父表的 `PRIMARY KEY` 或 `UNIQUE` 欄位**。範例資料庫中的三張父表尚未設定主鍵。 | 先透過 `ALTER TABLE` 將三張父表的參照欄位設為 `NOT NULL`，並補上 `PRIMARY KEY`。 |
| **3. 重複資料阻擋主鍵** | `訊息 1505：duplicate key value is (S108)` | `PRIMARY KEY` 底層依賴唯一索引，要求欄位值 100% 唯一。`學生` 資料表中存在多筆 `S108`，導致建立主鍵被中斷。 | 使用 `ROW_NUMBER()` 搭配 `CTE` 找出重複資料，每個編號僅保留 1 筆，安全刪除多餘的重複列。 |
| **4. 欄位型別不一致** | 課本寫 `char`/`varchar`，實際資料庫為 `nvarchar` | SQL Server 規定外鍵與被參照的主鍵必須具備**完全相同的資料型別與長度**，否則會報型別不相符錯誤。 | 全面統一採用 `nvarchar(4)`、`nvarchar(5)`、`nvarchar(8)`。 |

## 3. 完整解決步驟（直接複製至 SSMS「新增查詢」執行）

### 步驟一：檢查並清理父表重複資料（解決 `S108` 訊息 1505）

```sql
USE 教務系統;
GO

-- 1. 檢查三張父表是否有重複的主鍵編號
SELECT '學生' AS 資料表, 學號 AS 重複編號, COUNT(*) AS 筆數 FROM 學生 GROUP BY 學號 HAVING COUNT(*) > 1
UNION ALL
SELECT '教授', 教授編號, COUNT(*) FROM 教授 GROUP BY 教授編號 HAVING COUNT(*) > 1
UNION ALL
SELECT '課程', 課程編號, COUNT(*) FROM 課程 GROUP BY 課程編號 HAVING COUNT(*) > 1;
GO

-- 2. 安全去重：針對【學生】表每個學號只保留第 1 筆，刪除多餘重複列（如重複的 S108）
WITH CTE AS (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY 學號 ORDER BY (SELECT NULL)) AS rn
    FROM 學生
)
DELETE FROM CTE WHERE rn > 1;
GO
```

### 步驟二：為三張父表補上 `PRIMARY KEY`（統一使用 `nvarchar`）

```sql
USE 教務系統;
GO

-- 確保參照欄位為 NOT NULL，再建立主鍵
ALTER TABLE 學生 ALTER COLUMN 學號 nvarchar(4) NOT NULL;
ALTER TABLE 學生 ADD PRIMARY KEY (學號);

ALTER TABLE 教授 ALTER COLUMN 教授編號 nvarchar(4) NOT NULL;
ALTER TABLE 教授 ADD PRIMARY KEY (教授編號);

ALTER TABLE 課程 ALTER COLUMN 課程編號 nvarchar(5) NOT NULL;
ALTER TABLE 課程 ADD PRIMARY KEY (課程編號);
GO
```

### 步驟三：防呆刪除舊表並建立【班級】與 `FOREIGN KEY` 關聯

```sql
USE 教務系統;
GO

-- 若原本已存在【班級】資料表先移除，避免重複建表報錯
IF OBJECT_ID(N'dbo.班級', N'U') IS NOT NULL
    DROP TABLE dbo.班級;
GO

-- 建立【班級】資料表（全部文字欄位統一使用 nvarchar）
CREATE TABLE 班級 (
    教授編號 nvarchar(4) NOT NULL,
    課程編號 nvarchar(5) NOT NULL,
    學號     nvarchar(4) NOT NULL
             REFERENCES 學生 (學號),
    上課時間 datetime,
    教室     nvarchar(8),
    PRIMARY KEY (學號, 教授編號, 課程編號),
    FOREIGN KEY (教授編號) REFERENCES 教授 (教授編號),
    FOREIGN KEY (課程編號) REFERENCES 課程 (課程編號)
);
GO
```

### 步驟四：驗證與呈現作業結果

```sql
USE 教務系統;
GO

-- (A) 呈現資料表欄位結構（剛建完會顯示 5 個欄位表頭）
SELECT * FROM 班級;

-- (B) 檢視完整主鍵與 3 組外鍵約束證明
EXEC sp_help '班級';
```

> **提示**：若要截圖展示視覺化關聯，可在 SSMS 左側「物件總管」展開 `教務系統` $\rightarrow$ 右鍵「資料庫關聯圖」$\rightarrow$「新增資料庫關聯圖」$\rightarrow$ 全選 `班級`、`學生`、`教授`、`課程` 四張表，即可看到完整的 3 條外鍵連線。
